# FounderFit Candidate Assessment

FounderFit is a two-sided founder–asset matching tool. Rather than asking whether someone is a good founder in general, it evaluates whether a candidate is the right founder for a specific, already-validated technology asset.

Candidates are measured on three groups of dimensions:

- **Disposition (P1–P9):** stable traits that a venture has to be designed around, such as ambiguity tolerance.
- **Capability (C1–C8):** learnable competencies that close in 90–180 days with support, such as market translation.
- **Adjacency (J1–J5):** the candidate's position relative to this asset, such as domain credibility and buyer-market access.

## Features

- **Assessment flow:** timed forced-choice blocks, situational-judgment scenarios, calibration items, and assessor-rated adjacency.
- **Deterministic scoring:** a fit index (FFI), band, gates, gaps, risk flags, and a recommended configuration, computed in the browser.
- **Google sign-in:** every user signs in with Google and can only see and change their own assessments.
- **Saved reports:** each completed assessment (including every re-score) is saved to Cloud Firestore.
- **AI narrative:** an optional written report generated by Gemini on Vertex AI through a server route, with a deterministic fallback when the model is unavailable.
- **PDF export:** print styles produce a clean report via the browser's "Save as PDF".

## Data model and security

Assessments are stored at `users/{uid}/assessments/{assessmentId}`. Each document holds the candidate name, asset, score, band, validity status, versions, the context answers (`K1`–`K10`), the full scoring report, the narrative (initially `null`), and server timestamps.

The rules in `firestore.rules`:

- allow a signed-in user to read, create, and delete only their own assessments;
- require the exact set of fields on create, with type and range checks;
- allow only the `narrative` and `updatedAt` fields to change after creation;
- deny everything else.

The narrative route rejects requests without a valid Firebase ID token (`401`) or with bodies over 200 KB (`413`), and keeps the prompt on the server.

## Local setup

1. Install dependencies:

   ```bash
   npm ci
   ```

2. Create `.env.local` from the example and fill in the Firebase web app config (Firebase Console → Project settings → Your apps → *FounderFit Web*):

   ```bash
   cp .env.local.example .env.local
   ```

3. Start the development server:

   ```bash
   npm run dev
   ```

   Open http://localhost:3000 and sign in with Google. `localhost` is an authorized sign-in domain by default.

In development, the intro and header show sample-candidate buttons and the results page shows the save status. Both are hidden in production builds. Add `?fsdebug` to the URL to print Firestore debug logs in the browser console.

## Environment variables

Next.js only exposes variables prefixed with `NEXT_PUBLIC_` to the browser. The Firebase web config values are not secrets; access to data is enforced by the Firestore rules.

| Variable | Where | Required | Purpose |
|---|---|---|---|
| `NEXT_PUBLIC_FIREBASE_API_KEY` | browser | yes | Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | browser | yes | Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | browser | yes | Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | browser | yes | Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | browser | yes | Firebase web app config |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | browser | yes | Firebase web app config |
| `GOOGLE_CLOUD_LOCATION` | server | no | Vertex AI location, default `us-central1` (use `global` if the model returns 404) |
| `GEMINI_MODEL` | server | no | Gemini model, default `gemini-3.5-flash` |
| `GEMINI_API_KEY` | server | no | **Local development only.** Uses the Gemini Developer API instead of Vertex AI. Ignored in production. |
| `NEXT_PUBLIC_FIRESTORE_EMULATOR_HOST` | browser | no | **Local development only.** Points the app at a local Firestore emulator, e.g. `127.0.0.1:8085`. |

Never commit `.env.local`, never prefix `GEMINI_API_KEY` with `NEXT_PUBLIC_`, and never add it to `apphosting.yaml`.

## AI narrative locally

The narrative route calls Gemini in one of two ways:

- **Vertex AI (default, same as production).** Sign in with Application Default Credentials. Your account needs permission to call Vertex AI (`roles/aiplatform.user`):

  ```bash
  gcloud auth application-default login
  gcloud auth application-default set-quota-project founder-fit-6a455
  ```

- **Gemini Developer API (optional).** Set `GEMINI_API_KEY` in `.env.local` with a key from Google AI Studio.

If the call fails, the report shows the deterministic fallback narrative instead.

## Tests

```bash
npm test                 # unit tests: narrative route and Gemini client (mocked, no network)
npm run test:firestore   # Firestore rules and save tests in the local emulator
```

`npm run test:firestore` starts the Firestore emulator under the offline project ID `demo-founder-fit` on port 8085, so it never touches the real database. It needs the Firebase CLI and Java 21+.

To try the full app against the emulator instead of the real database:

```bash
firebase emulators:start --only firestore --project founder-fit-6a455
# then set NEXT_PUBLIC_FIRESTORE_EMULATOR_HOST=127.0.0.1:8085 in .env.local and run npm run dev
```

## Deployment (Firebase App Hosting)

The app is deployed by the App Hosting backend **`founder-fit`** in **`us-east4`**, connected to this GitHub repository:

- **URL:** https://founder-fit--founder-fit-6a455.us-east4.hosted.app
- **Root directory:** `/`
- **Runtime:** `nodejs22`
- **Rollouts:** automatic on every push to the live branch

`apphosting.yaml` defines the run config (0–2 instances) and the environment variables above. It contains no secrets: on App Hosting, Vertex AI is called with the backend's service account, `firebase-app-hosting-compute@founder-fit-6a455.iam.gserviceaccount.com`, which needs `roles/aiplatform.user`.

### Deploying Firestore rules and indexes

Rules and indexes are not deployed by App Hosting. After changing `firestore.rules` or `firestore.indexes.json`, run the emulator tests, then:

```bash
firebase deploy --only firestore --project founder-fit-6a455
```
